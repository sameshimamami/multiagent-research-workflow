# skill: 会议审稿（顶会级同行评审 · 双模型 · 两轮）

> 用途：**用两个独立"审稿人"（网页版 GPT + Claude）对自己的论文做顶会级评审**，两轮迭代，重点抓**细节与数据**。
> 来源：多智能体科研工作流实战 + `论文精读` skill 的"必须真读原文"纪律 + 安徽省基金申报书 30 轮迭代中沉淀的核查方法。
> 配套：写作约束见 `docs/academic-writing-constraints.md`；读论文画像见 `docs/论文精读.md`；桥接工具见 `bridge/bridge.js`。

---

## 触发方式

- **用户**："帮我审这篇""模拟 ICLR 审稿""review 一下这份稿子""按 NeurIPS 标准挑毛病"。
- **执行智能体**：`使用 会议审稿 skill 审 <论文路径>，目标会议 <ICLR/NeurIPS/ACL/AAAI/自定义>`。
- 投稿前自查、rebuttal 准备、导师/合作者互审，都走本 skill。

---

## 〇、三条不可违背的原则

1. **审稿人必须真的读论文**——把 PDF/全文**作为附件上传**给 GPT 和 Claude，要求它们**先读原文再评**。
   **不许凭记忆或标题猜**。凡是无法从原文核实的，标 `(未能核实)`，**不许编造**。
   （来源：`论文精读` skill 的教训——同一批论文，凭记忆的一方标了 84 处"未能核实"，真读原文后才拿到可用结论。）
2. **两个审稿人必须独立**——第一轮**互不看对方的意见**（开两个独立对话）。这样**两方都指出的问题→高置信**，**只有一方指出的→待判**。
3. **不留情面，但可操作**——每个批评必须①定位到具体位置（章节/行/表/图）②说明为什么是问题③给出**可执行的修改方向**。**禁止**"建议进一步加强实验"这类空话。

## 一、按会议的评审维度

先声明目标会议，让审稿人**用该会议的评审表**。

### ICLR / NeurIPS（通用机器学习顶会）

| 维度 | 判据 |
|---|---|
| **Soundness（正确性）** | 假设是否成立？推导是否有误？实验是否支持结论？基线是否公平？ |
| **Presentation（表达）** | 结构是否清晰？符号是否一致且已定义？图表是否自洽？ |
| **Contribution（贡献）** | 新颖性 vs 已有工作（**逐篇对比，不接受"我们首次…"式断言**）？对该领域的推进幅度？ |
| **Rating** | 1–10（或会议的对应刻度） |
| **Confidence** | 1–5，并说明审稿人自认的专业匹配度 |
| **Limitations / Ethics** | 作者是否诚实交代局限？有无夸大声称？ |

### ACL / EMNLP / NAACL（NLP）

- **Novelty**、**Soundness**、**Substance**、**Clarity**、**Meaningful Comparison**（是否与最强基线比）、**Reproducibility**、**Recommendation**（如 5=borderline）。
- 特别注意：**数据泄漏**、**标注一致性**、**是否只在自家数据集上有效**、**统计显著性**。

### AAAI / IJCAI

- **Technical Quality**、**Originality**、**Significance**、**Clarity**、**Relevance to Track**、**Overall**。

> ⚠️ 若用户没指定会议，**默认按 ICLR/NeurIPS 表**，并额外加 ACL 的 Novelty/Reproducibility 两项。

## 二、两轮流程

### 第一轮：独立首轮评审

**并发开两个对话**（GPT 一个、Claude 一个），各自上传论文，用**同一份评审提示词**，但**互不透露对方的意见**。

每个审稿人产出（见第四节模板）：
- 摘要复述（**证明它真读了**）
- Strengths（3–5 条，每条要有证据位置）
- **Weaknesses（5–10 条，按严重度排序）**
- **细节与数据核查表（见第三节，必做）**
- Questions to Authors
- Limitations
- 各维度打分 + Overall Rating + Confidence
- **明确的倾向**：Accept / Borderline / Reject，并说明"若只修 X 就能翻案"

### 交叉比对（由执行智能体做，不交给模型）

把两份评审合并成一张表：

| 问题 | GPT 是否指出 | Claude 是否指出 | 置信度 | 严重度 |
|---|---|---|---|---|
| … | ✅ | ✅ | **高**（两方共识） | 致命/重要/次要 |
| … | ✅ | — | 中（待判） | … |
| … | — | ✅ | 中（待判） | … |

**处理规则**：
- **两方共识 + 致命/重要** → 必改
- **一方指出 + 致命** → 作者判断（可能要补实验或核实）
- **两方都指出但互相矛盾**（一个说 A 是问题、另一个说 A 没问题）→ **标 `需裁决`**，作者回原文判断
- **只有一方指出 + 次要** → 酌情

### 作者修改

按上面的表逐条处理，**逐条留痕**（改前→改后）。

### 第二轮：复审

**关键**：第二轮要把**第一轮的评审意见 + 作者回应/修改说明**一起给审稿人，让它做**复审**而非重新评审。要求：

1. **逐条核对**第一轮每条问题的状态：`已解决 / 部分解决 / 未解决 / 作者反驳且反驳成立`
2. **检查修改是否引入新问题**（这是第二轮的重点——改一处常常坏一处）
3. **核查修改处与全文是否自洽**（术语、数字、图表编号、交叉引用）
4. **给最终建议**：`Accept / Minor Revision / Major Revision / Reject`，并说明**相比第一轮分数是否变化、为什么**

> **两轮之间的铁律**：第二轮**不许推翻自己第一轮没提出过的致命问题**——若确实发现新的致命问题，要明确指出"这是首轮遗漏，原因是什么"。

## 三、细节与数据核查清单（**本 skill 的重点**）

要求审稿人**逐项做**，并**逐条给出核对结论**。核查项：

### A. 表格与数字
1. **正文声称的数字**是否与**表格里的数字**一致？（逐处核对，常见错误：摘要写的提升幅度与表里对不上）
2. **表格内部**是否自洽？（同一指标在不同表的同一设置下应一致）
3. **与引用的原始论文比**：若表里抄了别人论文的数字，**与原文一致吗**？（常见：抄错、抄了不同设置的数）
4. **单位、小数位、正负号**是否统一？加粗/下划线是否标对了最优/次优？
5. **提升是否在噪声范围内**？（有没有报告标准差/种子数？差 0.3% 也号称"显著提升"？）

### B. 声称 vs 证据
6. **摘要/引言里的每一个 claim**，正文里都有对应实验吗？（逐条列，指出**无支撑的 claim**）
7. 有没有 **"首次""显著优于所有基线""全面超过"** 这类**过度声称**？
8. 结论是否**超出实验范围**？（只在一类数据集上做了，却声称通用）

### C. 实验设计
9. **基线是否公平**：同 backbone？同数据划分？同调参预算？**有没有漏掉最强基线？**
10. **消融是否支持归因**：去掉模块 X 掉点 → 能推出"X 是关键"吗？还是 X 只是增加了参数量？（**有没有等参数量对照？**）
11. **统计显著性**：关键结论有没有做显著性检验/多随机种子？
12. **是否只在自家数据/自家设定上有效**？

### D. 公式与符号
13. 每个符号**首次出现时是否定义**？全文是否**一符一义**？
14. 维度/下标是否对得上？推导有无跳步？
15. 公式编号是否被正文正确引用？

### E. 图表
16. 图与正文描述是否一致？（曲线趋势、标注的最优方法）
17. 坐标轴、单位、图例是否齐全？
18. 图注是否自足（不看正文能否看懂）？
19. 图表编号与正文引用是否对得上？

### F. 引用与相关工作
20. **引用的文献是否真实存在**？（重点核 arXiv 编号、会议名、年份——**猜错 ID 很常见**）
21. **有没有误引**（引它支撑一个它并不支持的论断）？
22. **是否漏掉最相关的近期工作**？（让审稿人主动列 3–5 篇"作者应该引但没引"）
23. 文献表格式是否统一？预印本是否被误标为正式发表？

### G. 可复现性
24. 数据集、划分、超参、评价指标是否给全？
25. 有无代码/数据链接？（若无，是否说明原因？）
26. 计算资源是否报告（GPU 型号/数量/时长）？

### H. 写作硬约束（叠加 `academic-writing-constraints.md`）
27. 二元对立句式（不是…而是…／而非／而不是）
28. 过度声称词（首次／全面／彻底／显著／真正）
29. 单一主导问题 vs 并列论点堆砌

> **输出要求**：这张清单**逐条给结论**（`通过 / 有问题（指明位置）/ 无法核实`），**不许跳过**。

## 四、输出格式（给审稿人的模板）

```markdown

目标会议：<ICLR/NeurIPS/ACL/AAAI>　评审人：<GPT/Claude>

用 5–8 句准确复述论文做了什么、方法核心、主要结论。
（不许复制摘要原文，要自己组织——这能验证是否真读懂。）

## 2. Strengths（3–5 条）
- S1：<具体点>（位置：§3.2 / 表 2）

## 3. Weaknesses（按严重度排序，5–10 条）
- W1 [致命]：<问题>（位置：…）—— 为什么是问题：… —— 建议：…
- W2 [重要]：…
- W3 [次要]：…

## 4. 细节与数据核查表（逐条，见提示词附的清单）
| 核查项 | 结论 | 位置 | 说明 |
|---|---|---|---|
| 正文数字 vs 表格 | 通过 / 有问题 / 无法核实 | … | … |

## 5. Questions to Authors
1. …
（每条都应是"回答后能影响我的评分"的问题）

## 6. Limitations
作者已交代的局限 / 未交代但应交代的局限。

## 7. 评分
- Soundness: x/4　Presentation: x/4　Contribution: x/4
- Overall Rating: x/10　Confidence: x/5
- **倾向：Accept / Borderline / Reject**
- **翻案条件**：若修好哪几条，我会改投 Accept。
```

## 五、评审纪律（写进给审稿人的提示词）

1. **先读原文再评**；无法核实的标 `(未能核实)`，**不许编造数字、论文、实验**。
2. **不许客套**：不要因为"写作清晰""选题重要"就放过方法缺陷；**你的价值在于找问题，不在于鼓励**。
3. **每条批评都要可操作**：定位 + 原因 + 修改方向，三样齐全。
4. **区分致命 / 重要 / 次要**——不要把格式问题和方法缺陷并列。
5. **不许提无法核实的批评**（如"我怀疑作者没跑够种子"→ 应先看它有没有写种子数）。
6. **主动找漏引**：列出 3–5 篇"作者应该引用但没引"的相关工作（**必须真实存在**，给链接）。
7. **主动找反例**：作者的某个 claim 有没有已被发表的**反例论文**？有就直接点名。
8. **诚实标注专业边界**：不熟的子领域要说 Confidence 低，别硬评。

## 六、执行流程（执行智能体照此走）

```
① 确认目标会议 + 拿到论文全文（PDF/LaTeX/Markdown）
        ↓
② 并发开两个独立对话：GPT 一个、Claude 一个
   ├─ 上传论文全文
   ├─ 发同一份首轮评审提示词（含第四节模板 + 第三节核查清单 + 第五节纪律）
   └─ ⚠️ 互不透露对方意见；要求真读原文
        ↓
③ 收两份评审 → 执行智能体做交叉比对表（共识/单方/矛盾）
        ↓
④ 作者按表逐条修改，留痕（改前→改后）
        ↓
⑤ 第二轮：把「第一轮评审 + 作者回应/修改说明 + 修改后的论文」发给同两个审稿人
   └─ 要求：逐条核对状态 + 找新引入的问题 + 给最终建议
        ↓
⑥ 再次交叉比对 → 输出「最终修改清单」
```

### 操作要点
- **上传用唯一文件名**（如 `v1_r1.pdf`、`v2_r2.pdf`）——同一对话多次上传同名文件，模型会读到旧版本（实测踩过）。
- **网页模型有工具循环风险**：若某方陷入"反复读 PDF"不产出，**减小论文切分粒度、明确要求"先给评审再补引用"、限制读取次数**。
- **额度用尽自动等恢复**，不问用户。
- 每轮产出**存档**（`review_r1_gpt.md` / `review_r1_claude.md` / `review_r2_*.md` / `fixlist.md`），第二轮和 rebuttal 都要用。
