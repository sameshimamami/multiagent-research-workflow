# skill: 科研申报书写作（科研项目申报书 · 写作与修改）

> 用途：撰写或修改科研项目申报书（省/国家自然科学基金、面上/青年项目、开题与结题报告等）时调用。
> 来源：提炼自 2026-09 安徽省自然科学基金申报书的多轮实战——**导师（通讯作者）逐段 Word 批注 12 条 + GPT/Claude 两轮全文审计 + 8 轮修改（v18→v25）**。
> 配套：写作硬约束见同目录 `academic-writing-constraints.md`（禁二元对立句式、禁过度 claim 等），本 skill 与其**叠加使用**。
> 使用方式：任务前把本文件附到 prompt 开头；完成后按「第七节 提交前自检清单」逐条扫描。

## 一、第一性原理：申报书的三层结构（先分清，再动笔）

评审读申报书，其实在连续回答三个问题。**写作者最常见的错误就是把这三层混在一起**：

| 层级 | 回答什么 | 例（本案） | 判据 |
|---|---|---|---|
| **研究场景** | 在哪儿做 | 工业知识图谱 | 提供实例与数据来源 |
| **研究对象／主题** | 做什么 | 开放动态环境下图—语言模型的协同高效适应 | 界定对象与范围 |
| **科学问题** | 为什么／如何 | 图结构知识与语言语义知识在持续演化条件下的双向迁移机理与协同更新规律 | 指向**机理或规律**，可被理论分析与实验检验 |

**铁律：**
1. **「研究意义」这一节的功能是论证科学意义，不是介绍应用场景。** 行业应用可以出现，但要降为"典型验证场景"，绝不做论证的终点。
2. **研究主题 ≠ 科学问题。** 把主题当科学问题写，是本类材料最常见的失分点；评审会追问"你到底要揭示什么规律"。正确写法是**两句并置**：先给主题，再给科学问题。
3. **抽象层级必须一致。** 三个并列的"挑战"若分别落在「领域／数据现象／模型关系」三个层级上，读者必然看不出内在逻辑。

## 二、导师 12 条批注 → 通用规则

> 以下每条：**批注原话 → 通用规则 → 怎么查 → 怎么改**。
> 这些规则不限于某个项目，任何申报书都可套用。

### 规则 1｜研究对象要有"特点"，并交代适用边界（批注 #0）
- **原话**：「以下讨论是否都是基于工业知识图谱？工业知识图谱有何特点？这些挑战在其他领域知识图谱是不是都适用？」
- **规则**：用了限定性场景名（工业/医疗/金融知识图谱），就必须（a）说明该场景的**特点**，（b）说明结论**是否可推广**，否则读者会认为你的问题只是工程细节。
- **怎么查**：全文搜场景限定词；看它是否只在标题里出现、正文从未交代特点；检查有没有"一边限定、一边把不属于该场景的例子算进来"的自相矛盾（本案：说"工业知识图谱"，却把医疗、电商列为应用）。
- **怎么改**：开场补特点 + 把限定场景降为"典型场景/典型验证场景"，问题向共性问题抽象；研究主题里的场景限定改为更一般化的说法。

### 规则 2｜挑战名必须自解释、同层级、有内在逻辑（批注 #1）
- **原话**：「三类挑战具体指什么？要分开写……1. 内在逻辑不清晰；2. 名称凝练的不够好，比如：图智能，读者很难从这个题目中猜测出是什么挑战。图智能这个问题太大太大，从下面的关键问题看出应该是所谓'关系可靠维护'，但'关系可靠维护'这个词凝练的也不够好。」
- **规则**：
  - **名称自解释**：读者只看名字就能猜到问题。用「**对象 + 动作**」结构最稳（如"演化关系的可信维护""多轴漂移下的持续适应"）。
  - **同层级**：不能一个是学科领域、一个是数据现象、一个是模型关系。
  - **内在逻辑**：并列 ≠ 逻辑。要写成**递进链**（如"关系维护 → 稳定适应 → 协同更新"），并写明"前者输出即后者输入"。
  - **避免过大或过窄的词**：过大的（"图智能"）像领域名；过窄的（"关系可靠维护"）看不出对象与动作。
- **怎么查**：把三个名字单拎出来问"这是什么层级"；看有没有"图/智能/协同"这类**领域词**被当成挑战名；看三个名字是否同一语法结构。
- **怎么改**：统一改造为「对象+动作」；把并列改成递进并显式写依赖；同步改到全文所有出现处（研究内容／研究目标／关键科学问题／研究方案／创新点／预期成果／可行性／研究基础）。

### 规则 3｜指代必须落名，不能靠读者回翻（批注 #2）
- **原话**：「哪两类工作？指向不明。」
- **规则**：凡用"两类工作""上述方法""相关工作"这类**回指**，若前文跨度超过一两句，必须**直接点名**（谁、哪篇、做了什么）。
- **怎么查**：搜"两类/三类/上述/该类/相关工作"，逐个确认指代对象是否在**紧邻上文**。
- **怎么改**：改成"前者只调整图（[60]），后者只调整模型（[59]）"式。

### 规则 4｜导师的反问句 = 你的句子缺主语（批注 #3）
- **原话**：「这里是不是指图谱改善与智能体能力提升相互反馈？」
- **规则**：导师用"是不是指……？"来问，通常不是他没读懂，而是**你的主语／宾语缺失**——他只能靠猜。
- **怎么查**：找出所有"未建立…机制""难以…""缺少…"这类无主语否定句。
- **怎么改**：补全"**谁**和**谁**之间"的关系，让闭环在段内闭合。

### 规则 5｜"研究意义"必须按四步写，且团队基础要如实（批注 #4）
- **原话**：「这一段和上面的一段有一些共性的问题，逻辑上有跳跃，读者难以理解。每个问题的描述可以按照一个思路：首先介绍这个问题是什么？再次归纳现有工作以及现有工作的缺陷/遗漏，再介绍本团队的工作基础，最后再介绍本项目拟就此问题开展具体的研究。总体要简短，后面还会深入讨论这些。」
- **规则**：每个挑战统一按 **四步**：① **是什么** → ② **现有工作及缺陷/遗漏** → ③ **团队工作基础** → ④ **本项目拟开展什么**。总体简短。
- **关键陷阱**：**团队基础不得过强**。若可行性分析里自认"尚未覆盖 X"，研究意义里却写"积累了方法基础"，就是**同一份材料前后不一致**，评审必抓。诚实的写法是："团队前期在 A 方面开展了研究，但面向的是 A′，**尚未涉及** X"。
- **怎么查**：看每个挑战是否四步齐全；"现有工作"是否**带引用**（本案有两段原本没引用）；"拟开展"是否只是**复述挑战名**（那是无效信息）；段间是否有**逐字重复**的句子。
- **怎么改**：按四步重排；补引用；复述句改写成具体机制；删重复句。

### 规则 6｜术语含糊要就地定义（批注 #5）
- **原话**：「什么数据流？是指模型训练的数据流？」
- **规则**：任何**多义术语**首次出现必须限定（如"数据流" → "模型持续接收的无标签图数据流"）。顺带把该术语**依赖的前提**一并交代（此处即"无标签"）。
- **怎么查**：搜"数据流/环境/任务/知识"这类泛词，看首次出现有没有限定。

### 规则 7｜术语分层要显式且唯一；元指令不能写进正文（批注 #6）
- **原话**：「？？这个要统一一下，多层次分布漂移或者多轴漂移。」
- **规则**：
  - **一个概念只保留一套说法。** 若确有标题层／技术层两层术语，必须在**首次出现处显式声明对应关系**（"这里的 X 具体对应 Y…"）。
  - **绝不把"正文技术表述统一采用……"这类写给自己的写作约定留在正文里**——导师的"？？"就是冲它来的。
  - 选词要给理由：「层次」暗示嵌套，「轴」暗示并列——四个并列维度用"轴"更贴切；"多轴复合"还能直接表达"多轴同时变化"。
- **怎么查**：全文搜同义术语（多层次/多轴/多层）；搜"统一采用""本文统一""下称""以下简称"——确认这些是否该出现在正文。

### 规则 8｜俗称首次出现必须给全称与映射（批注 #7）
- **原话**：「大模型指大语言模型；小模型指图神经网络模型？」
- **规则**：任何**俗称／缩写**（大模型/小模型/大语言模型/GNN）首次出现必须写全称并给出下称映射：「大语言模型（下称大模型）」「轻量图神经网络（下称小模型）」。
- **怎么查**：搜所有简称，确认首现处有定义。

### 规则 9｜不要强加"矛盾"，先检查逻辑是否真成立（批注 #8）
- **原话**：「严格来说，这里没有矛盾。上面只是介绍了大模型和 GNN 各自特点。」
- **规则**：**"矛盾"需要互斥，互补不是矛盾**。若上文只是并列介绍各自优缺点，"围绕这一矛盾"就是逻辑强加，有经验的评审一眼看穿。改用"二者优势互补""效率与精度的权衡"。
- **怎么查**：搜"矛盾/冲突/悖论"，逐个回看上文是否真的论证了互斥。

### 规则 10｜研究主题 ≠ 科学问题（批注 #9）
- **原话**：「这个不是核心问题，是研究主题。科学问题应该是类似：图结构知识与语言语义知识在持续演化条件下的双向迁移机理与协同更新规律之类的。」
- **规则**：区分见第一节表格。**科学问题必须写成"……机理与……规律"式，可被理论分析与实验检验**。
- **怎么查**：搜"核心科学问题"——若后面跟的是一个名词短语（××的协同高效适应），就是主题当科学问题写。
- **怎么改**：改为**两句并置**：「本项目以"…"为**研究主题**，拟聚焦的**科学问题**是：……」；并把「关键科学问题」节的问题名改成**问题式**表述（如何…）。注意：导师给的例句往往只覆盖其中一个挑战，要**扩写至覆盖全部挑战**。

### 规则 11｜中文申报书：关键词首次括注英文，之后用中文（批注 #10）
- **原话**：「关键词尽量不用英文。」
- **规则**：`label shift` → **标签分布偏移（label shift）**、`concept drift` → **概念漂移（concept drift）**、`SFT` → **监督微调**；**只在首次出现处括注**，之后一律中文。`OOD` → 分布外（OOD）；`Prompt` → 提示。
- **易错点**：**括注位置要前移到真正的首次出现处**（本案括注原本在文献综述节，而首次出现在研究意义）。改完要全稿搜一遍同名英文，逐一处理。

### 规则 12｜先立共性科学问题，行业应用降比重（批注 #11）
- **原话**：「我们暂时不考虑行业问题，先找出共性问题。」
- **规则**：**「研究意义」的收尾顺序应为：共性问题 → 科学问题 → 理论价值 → 方法可迁移**。行业场景挪到"典型验证场景"或可行性/预期成果节，且**不要列举多个行业的扩展场景**。
- **怎么查**：搜具体行业名与地域名（智能客服/智慧医疗/电商推荐/实时问答/某省某企业）——凡出现在"研究意义"或方法论证句里，即为越位。

## 三、结构模板

### 「研究意义」推荐结构（可直接套）

```
1. 政策与产业背景          （1–2 句，交代申报背景）
2. 研究对象及其特点         （点明限定场景的 2–3 个特点）        ← 规则 1
3. 定位声明               （"XX 是典型场景；以下抽象出共性问题"）  ← 规则 1/12
4. N 个共性挑战（总述）     （同层级、自解释、含递进关系）          ← 规则 2
5. 其一，〈对象+动作〉是〈核心瓶颈〉：是什么 → 现有工作及缺陷 → 团队基础 → 拟开展   ← 规则 5
6. 其二 ……（同四步，简短）
7. 其三 ……（同四步，简短）
8. 收尾：研究主题 + 科学问题 → 理论价值 → 方法可迁移               ← 规则 10/12
```

### 挑战六段/三段句式模板

- **总述**：`从上述场景中可以抽象出 N 个共性挑战：〈挑战一〉是〈搭配词〉，〈挑战二〉是〈搭配词〉，〈挑战三〉是〈搭配词〉。三者沿"〈环节一〉—〈环节二〉—〈环节三〉"递进：〈前者输出即后者输入的具体说明〉；〈末环节的结果又回馈首环节〉。`
- **分述开头**：`其N，〈对象+动作〉是〈核心瓶颈/关键空白/根本难题〉：〈问题的一句话定义〉。`

## 四、术语与口径纪律

1. **首次括注英文、后续中文**（规则 11）。
2. **术语分层显式声明且只说一次**；元指令不进正文（规则 7）。
3. **封闭集合不要写"等"**：如"时序漂移、结构偏移、标签分布偏移与概念漂移"是**封闭四元组**，加"等"会把它变成开放集，与后文的实验条件设定冲突。
4. **全称判断必须逐篇核实**（见第五节）。
5. **同一个概念只留一套主线标签**：本案曾同时存在四套（"知识状态维护—模型持续适应—异构模型协同更新"／"关系维护—稳定适应—协同复用"／"知识可靠演化—模型能力保持—模型协同利用"／"关系状态维护—动态图稳定适应—图—语言协同复用"），必须收敛为一套。
6. **命名在多处出现时必须同步**：标题 ↔ 研究内容 ↔ 研究目标 ↔ 关键科学问题 ↔ 研究方案 ↔ 创新点 ↔ 预期成果，一处漏改就是"前后对不上"。

## 五、事实核查纪律（本类材料的高危项）

| 高危类型 | 本案实例 | 核查方法 |
|---|---|---|
| **全称判断** | "现有工作**均一次只处理一类变化**"——而 [69] ODS（ICML 2023）的核心贡献恰是**同时**处理两类偏移 | 凡"均/全部/大多/从不/首次"，**逐篇读摘要与问题定义节**确认；改法是把断言换成**更强的真命题**（"已有工作至多联合处理两类偏移，均未同时耦合 A、B、C"） |
| **文献状态写错** | 把已正式发表的论文（*Applied Intelligence*, 2024）写成"SSRN 预印本，未经同行评审" | 每篇引用核对**发表状态与出处**；已发表的不标注为"在投/预印本/未经评审" |
| **引用超出证据范围** | 用不变性方法（IRM/DIR/CIGA）支撑"从连续时间窗口提取重复出现局部子图"这一具体操作 | 逐条问"这篇文献**字面上**支持这句话吗" |
| **引用挂载不成比例** | 17 个编号一次性堆在句末，与句中四个名词对不上 → 读来像"为了让所有文献都有落点而硬塞" | 按概念**分组挂载**：`图神经网络[8][9][10]、图Transformer[49][50]、图预训练[11][12]…` |
| **无可核证来源的数字/企业名** | "科大讯飞、华米科技等……""覆盖千万级实体、亿级关系"——查不到来源，参考本里也没有 | 具体企业名＋具体规模数字必须有出处；无出处则改为不绑定的共性表述 |
| **算力等硬件数字与设备不符** | "FP64≥200TFlops、FP32≥3.0PFlops"与同段所列单卡不符 | 与**参考模板原话**对齐（本案按 2024 面上项目模板写，其口径为"GPU 总算力"集群级） |

## 六、多模型协作流程（推荐）

```
① 起草（GPT 或人）
      ↓
② 审计（Claude）：逐条列出「位置 ｜ 问题 ｜ 可直接替换的成句」
      ↓
③ 收敛（DSH/人）：合并两份意见、去重、标出需作者拍板的项
      ↓
④ 应用（Claude Code）：照抄审计给的成句，不自行润色；改动逐条留日志
      ↓
⑤ 复核（GPT + Claude）：确认没有新引入的矛盾，给「可以送审／还需修改」
```

**流程要点：**
- **审计意见必须落到"可直接替换的成句"**，否则应用环节会二次创作、偏离原意。
- **两份审计要合并去重**；模型会读错附件版本（本案 GPT 三次读到旧版），故**每次发附件必须用唯一文件名**（如 `v25.md`），不要反复用同名重传。
- **需要作者拍板的项要单独列出来**（任务定义、实名信息、无可核证的事实、模板数字），不要自行决定。

## 八、本案沉淀的"反模式"速查（写的时候就要避免）

1. ❌ 用**领域名**当挑战名（"图智能"）。
2. ❌ 三个挑战**不同层级**并列，逻辑靠"递进式约束"这类空话撑。
3. ❌ 把**研究主题**写成"核心科学问题"。
4. ❌ "研究意义"结尾**落到行业应用**（智能客服/智慧医疗/电商推荐）。
5. ❌ **团队基础写得比可行性分析强**，两节自相矛盾。
6. ❌ 挑战段**不引用**，全靠泛泛而谈。
7. ❌ "拟开展"只是**复述挑战名**。
8. ❌ 术语**两套并存**、或在正文里留写作元指令。
9. ❌ **全称判断**没逐篇核实，被反例打脸。
10. ❌ 把已发表论文写成"预印本/未评审"。
11. ❌ 为了让所有文献"都有落点"而**成堆塞引用**。
12. ❌ 引用**可核查的具体企业名与规模数字**却无出处。
