# 01 · 提示词生成规范（核心）

> 这是你特别强调的一环：**你输入时语言逻辑都是你自己的**，工作流里必须有一个智能体，
> 根据你的逻辑和内容生成提示词，再喂给干活的智能体。这个角色由 **DSH** 承担。

---

## 1. 定位

- **你**：只负责“说人话”。输入可以是口语、跳跃、逻辑完全按你的思路。
- **提示词生成器（DSH）**：把你的话转成**结构化提示词**，让 hermes / Claude Code 能直接照着干。
- **干活智能体**：只收到标准提示词，不需要理解你的原始表述。

一句话：**你负责“意图和内容”，生成器负责“翻译成任务”，干活智能体负责“执行”。**

---

## 2. 生成器的五步工序（DSH 每次都走）

1. **意图解析**：判断任务类型（记笔记 / 建链 / 找论文 / 创新点 / PPT / 改代码 / 跑实验），
   识别你真正想要什么。
2. **上下文补全**：读 `02-Obsidian笔记规范.md`、`templates/` 对应模板、**先查 `index/工作流记忆.md` 看有没有踩过的坑**、并**真的去读 Vault 里的已有笔记**，
   把干活智能体需要但你没写的信息补上（文件路径、格式、应关联的笔记）。
3. **结构化**：套用对应模板，填充变量，产出标准提示词。
4. **校验（红线自查）**：
   - [ ] 你的原意、术语、方向没被改变或删减；
   - [ ] 补全的内容都标注为“补全”，不冒充你的意思；
   - [ ] 涉及关联笔记时，链接来自真实读到的 Vault 文件，不是凭空猜。
5. **分发**：附上“执行方式”（命令 / skill / 目标目录），路由给 hermes 或 Claude Code。

---

## 3. 红线原则

| # | 原则 | 反例 |
|---|------|------|
| 1 | **不曲解**：保留你的逻辑和结论 | 你写“我怀疑图密度加剧漂移”，生成器写成“图密度导致漂移”❌ |
| 2 | **不删减**：不丢你的要点 | 你提了 4 个动机，生成器只保留 3 个 ❌ |
| 3 | **不越界**：只补全执行所需，不加自己的“研究判断” | 你在想创新点，生成器擅自替你下结论 ❌ |
| 4 | **补全要标注**：补的信息标 `[补全]` | 偷偷补路径/格式而不说明 ❌ |
| 5 | **链接要真实**：关联笔记必须读过 Vault 才写 | 猜一个 `[[不存在]]` 的链接 ❌ |

---

## 4. 主模板（Master Prompt Template）

生成器产出的标准提示词统一用这个骨架：

```markdown
【任务目标】一句话：要做什么、产出什么
【任务类型】笔记 / 建链 / 找论文 / 创新点 / PPT / 改代码 / 跑实验
【背景与输入】你的原始内容（论文核心、领悟、点子），尽量原样保留
【产出物】文件类型 + 精确输出路径
【格式规范】引用 02-Obsidian笔记规范.md 或 PPT 规范的对应章节
【关联链接】[补全] 应与之建立 [[链接]] 的已有笔记清单（来自真实读到的 Vault）
【约束】语言、长度、风格、明确“不要做什么”
【验收标准】按 `templates/08` 打分表逐项 0/1，全 1 才算过（结构完整 / 链接有效 / 无溢出 / 能运行…）
【执行方式】给哪个智能体 + 调用方式（hermes / claude + ppt-master 等）
```

## 5. 正反例

### 你的原始输入（示例）

> “这篇 A-Mem 感觉就是给 agent 做长时记忆的，用图存经历然后检索，和我之前 Mem0 记的那种抽取更新不太一样，
> Mem0 是抽事实然后 ADD/UPDATE/DELETE，A-Mem 更像图上的节点经历。你帮我记一下，和我记忆相关的笔记都连上。”

### ❌ 错误生成（曲解 + 删减 + 乱猜链接）

> “写一篇关于 A-Mem 的笔记，说明它比 Mem0 好，链接到 [[长期记忆]]。”

问题：把“不太一样”曲解成“比 Mem0 好”；删了“图存经历/节点经历/抽取更新”等细节；链接没真读 Vault。

### ✅ 正确生成（保留逻辑 + 补全标注）

```markdown
【任务目标】在 Obsidian Vault\记忆\ 新建论文笔记《A-Mem》，记录其核心与用户领悟
【任务类型】笔记
【背景与输入】用户原话：A-Mem 是给 agent 做长时记忆，用图存“经历”，检索时取相关节点；
  与用户此前读的 Mem0（抽取事实→ADD/UPDATE/DELETE）不同：Mem0 是“事实抽取更新”，
  A-Mem 更像“图上节点经历”。用户原意是“两者机制不一样”，不要写成“孰优孰劣”。
【产出物】C:\Users\我\Documents\Obsidian Vault\记忆\A-Mem.md
【格式规范】按 02-Obsidian笔记规范.md 第 3 节“论文笔记模板”：frontmatter + 动机/方法/实验/结果/一句话汇报 + 结尾链接
【关联链接】[补全] 读 Vault 后判定相关笔记：[[Mem0]]、[[长期记忆]]、[[为什么需要记忆]]、[[RAG]]
【约束】中文为主，英文术语保留；结尾链接紧接正文；不要下“谁更好”的结论
【验收标准】笔记含 frontmatter 与完整章节；结尾 [[链接]] 全部指向 Vault 中真实存在的笔记
【执行方式】hermes（wsl -d Ubuntu 后 hermes），写入路径 /mnt/c/Users/我/Documents/Obsidian Vault/记忆/A-Mem.md
```

> 关键区别：✅ 版本**保留了你“机制不一样”的判断、保留了两个方法的具体区别，并把“读 Vault 后判定”的链接显式列出**；补全的信息都标了 `[补全]`。

---

## 6. 你只需这样输入（几种典型话术）

- 记笔记：“帮我把这篇《XXX》记一下，核心是……我理解是……和之前的连起来”
- 建链：“这篇/这些笔记帮我理一下关系”
- 找论文：“找几篇 XX 方向的，近三年 A 类”
- 想创新点：“结合我这些笔记，看看有没有可做的点子”
- 做 PPT：“拿这些笔记做份组会 PPT”
- 改代码：“项目在 XXX，我想……，你看着改”
- 跑实验：“在 XXX 项目跑 XXX，参数……，出结果”

你不需要写规范提示词；把“核心 + 你的领悟 + 大致要什么”说出来即可。
