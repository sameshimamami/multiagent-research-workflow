## 1. 角色分工

### DSH（我）—— 编排者 + 提示词生成器 + 关系/创新点大脑

唯一入口。所有任务先经过我，我不直接干“体力活”，负责“想清楚 + 分派 + 验收 + 记全局”。

| 职责 | 说明 |
|------|------|
| **提示词生成** | 把你的原始输入转成结构化提示词（见 `01-提示词生成规范.md`） |
| **任务路由** | 判断任务类型，分发给 hermes（文本）或 Claude Code（代码/PPT） |
| **结果验收** | 读回产物，校验是否符合规范（笔记格式、链接有效、PPT 溢出等） |
| **关系维护** | 读 Obsidian Vault，判定该与哪些已有笔记建立 `[[链接]]`，维护关系索引 |
| **创新点推理** | 结合“关系 + 笔记”想创新点，回写成笔记 |
| **找论文** | 用联网搜索（web_search），按你的研究领域搜近三年 A 类会议/期刊论文 |
| **全局记忆** | 每次任务的关键结论、进度记回 `research-workflow/`（或 Obsidian） |

### hermes —— 文本 / 研究智能体（“写”的主力）

| 职责 | 说明 |
|------|------|
| 读论文 / 看论文 | 把 PDF / 原文 / 摘要 → 结构化阅读 |
| 写 Obsidian 笔记 | 在 `C:\Users\我\Documents\Obsidian Vault\记忆\` 创建论文笔记（经 `/mnt/c/...` 访问，见 `03`） |
| 建链 / 维护关系 | 按 DSH 给的链接清单，在笔记结尾写 `[[...]]` |
| 写文案 | PPT 文案、组会讲稿、综述、审稿意见 |
| 自学 skill | 无需安装，给一份示例任务即可学会（用于 PPT 等，见 `03`） |
| **监督/验收** | 检查 DSH 的笔记、检查 Claude Code 的 PPT，给问题清单（见 `templates/08-监督验收.md`） |

### Claude Code —— 代码 / 工程智能体（“产出文件”的主力）

| 职责 | 说明 |
|------|------|
| 改代码 | 你只告诉“项目在哪 + 大致怎么改”，它读代码、定位、改、自测 |
| 跑实验 | 写训练/评测脚本、跑批、记录日志和结果 |
| 做 PPT | 安装 ppt-master skill（或用 PptxGenJS），直接生成 `.pptx` |
| 批量文件处理 | PDF 裁剪、格式转换、数据清洗等（参考你 `笔记/提示词.md` 里的任务） |

## 2. 核心流水线（每个任务都走这 6 步）

```
① 你的原始输入（论文核心 / 领悟 / 点子，语言逻辑是你自己的）
        │
        ▼
② 提示词生成（DSH）
   解析意图 → 读规范与已有笔记 → 补全上下文 → 套模板 → 生成结构化提示词
        │
        ▼
③ 路由分发（DSH）
   ├─ 文本类（笔记/综述/文案/建链/创新点文案）──► hermes
   ├─ 代码类（改代码/跑实验）──────────────────► Claude Code
   ├─ 产出类（PPT）──────────────────────────► Claude Code（ppt-master）
   └─ 搜索类（找论文）────────────────────────► DSH 自己（web_search）
        │
        ▼
④ 执行（干活智能体）→ 产物写回
   ├─ 笔记 ──► Obsidian Vault\记忆\
   ├─ 代码/实验 ──► 项目目录
   └─ PPT ──► 桌面 / 指定目录
        │
        ▼
⑤ 产出监督（打分 0/1 → 不过就 replan → 最多 2 轮 → 升级给你，见 templates/08）
   **所有产出**（笔记/建链/找论文/创新点/PPT/改代码/跑实验）各按 08 的对应打分表检查
   有 0 分项 → DSH 只针对该项重写提示词 replan → 复检
   通过后记 learn 到 index/工作流记忆.md
        │
        ▼
⑥ 关系维护 + 创新点 + 回执（DSH）
   更新 [[链接]]/关系索引 → 结合关系+笔记推创新点 → 给你简短回执
```

## 3. 路由规则（判断“派给谁”）

| 任务类型 | 关键词示例 | 派给 | 产物位置 |
|----------|-----------|------|----------|
| 读论文 → 记笔记 | “读一下这篇”“总结这篇” | hermes | `Obsidian Vault\记忆\` |
| 建链 / 补关系 | “和已有的笔记关联”“建链” | DSH 判链 → hermes 写 | `记忆\` 笔记结尾 |
| 找论文 | “找几篇 XX 方向的” | DSH（web_search） | 腾讯文档表格 / 笔记 |
| 想创新点 | “结合这些笔记想点子” | DSH 推理 + hermes 成文 | `记忆\` 新笔记 |
| 做 PPT | “做份 PPT”“组会汇报” | Claude Code（ppt-master） | 桌面 / 指定目录 |
| 改代码 | “改一下 XX 项目”“加个功能” | Claude Code | 项目目录 |
| 跑实验 | “跑一下”“调参”“出结果” | Claude Code | 项目目录 |

> 边界：**文字写进 Obsidian 的活给 hermes；改动文件系统/代码/生成 pptx 的活给 Claude Code；判断、搜论文、维护关系、想创新点由 DSH 兜底。**

## 4. 数据流（谁读写什么）

```
DSH ──读/写──► Obsidian Vault（写笔记 + 判关系）
DSH ──写──► research-workflow/（规范、模板、关系索引、进度）
hermes ──读/写──► Obsidian Vault（写笔记 + 监督验收）
Claude Code ──写──► 项目目录 / 桌面（代码、实验、.pptx）
hermes / DSH ──读──► 产出（监督验收：内容 + 结构）
```

关键约定：DSH 现有全量文件权限（danger-full-access），可直接读写 Vault；**生产由干活智能体完成、由另一智能体监督**——DSH 产笔记 → hermes 检，Claude Code 产 PPT → hermes + DSH 双重验收（见 `templates/08-监督验收.md`）。

## 5. 关系索引（本工作流的“全局记忆”）

`research-workflow/index/` 下维护一份轻量索引（后续落地时生成）：

- `关系索引.md`：主题 → 相关笔记文件清单（DSH 每次建链后更新）
- `进度.md`：每个任务的执行记录、产物路径、待办

这样即使换了会话，关系图和进度也能接续。
