# skill: 论文精读（论文 / 科研报告的结构化画像）

> 用途：读一篇论文、一批论文或一份科研报告时，按**固定的 14 组问题**产出结构化画像。用于快速判断"这篇工作到底做了什么、做到什么程度、我能不能复现"。
> 来源：作者（2026-09）原始提问模板 + 安徽省基金申报书实战中 18 篇论文的画像实践 + 多轮踩坑教训。
> 配套：写作类任务叠加 `academic-writing-constraints.md`；申报书任务叠加 `科研申报书写作.md`。
> 适用对象：论文（含预印本）、技术报告、结题报告、开源项目白皮书、竞品技术文档。

---

## 触发方式

- **DSH / Claude Code**：`claude -p "使用 论文精读 skill，读 XXX（路径或题目），输出 14 组画像"`，或把本文件附到 prompt 开头。
- **网页模型（GPT / Claude）**：把本文件 + 论文清单发过去，**必须同时附上第三节的「执行纪律」**（尤其禁用工具那条）。
- **人工**：需要快速摸清一篇工作在做什么时，照第二节逐条填写。

---

## 一、核心模板：14 组问题

> **这 14 组是固定格式，每次都用，顺序不要改。**新增维度时**追加**在末尾，不要重排。

### A. 定位与价值（1–5）

1. **题目**是什么？——给**英文原文全称** + 作者 + venue + 年份 + 链接
2. **主要研究内容**是什么？（3–5 句）
3. **已有工作的不足**是什么？——**论文自己怎么说的**，不要用你的判断替代
4. **动机（motivation）**是什么？——为什么非做这个不可
5. **用 30 个词总结它的方法**（中文，控制在 30 词上下）

### B. 实验与效果（6–11）

6. **使用的数据集**有哪些？
7. **评估指标**是什么？
8. **测试了哪些 backbone 模型**？
9. **本文的实验得分**是多少？（主要结果表的关键数字）
10. **超 previous SOTA 多少分**？——若论文没有明确对比，就说明**它对比了谁、差多少**
11. **做了哪几种实验**（主实验 / 消融 / 敏感性 / 可视化 / 案例研究 / 效率实验…）？**为什么做这几种**？

### C. 任务与可复现性（12–14）

12. **研究的是什么任务？任务的输入输出分别是什么？**
13. **有没有源代码开源？需要怎样的计算资源？**——给仓库链接；GPU 型号/数量/训练时长
14. **方法是什么？包括哪些模块？各个模块的功能分别是什么？**

> ⚠️ **第 5 组与第 14 组不重复**：第 5 组要**概括**（30 词），第 14 组要**拆解模块与各自功能**。用第 5 组的内容去填第 14 组是无效回答。

---

## 二、输出格式

- **每篇一个小节**，标题写 `## [编号] 论文简称`，下面按 1–14 编号作答。
- **不要跨论文合并回答**——列出的是逐篇画像，不是综述。
- 不要写引言或总结段落。
- **所有篇目回答完后**，可追加一节「**共性观察**」（≤200 字）：这些工作在**任务设定、评价方式、是否开源、计算规模**上的共同点是什么？

### 多篇时的分批策略（实测）

| 每批篇数 | 效果 |
|---|---|
| **2–3 篇**（要求**真读原文**时） | ✅ **推荐**。每篇都要检索+打开+读，2–3 篇是能读透的上限 |
| ≤6 篇（**凭记忆**作答时） | ✅ 实测可行（GPT 一批 6 篇可产出 2 万字级画像）——**但内容无法一手证实，只能当线索** |
| 7–12 篇 | ⚠️ 后半部分质量明显下降，且「未能核实」标注会变少（说明开始在编） |
| >12 篇 | ❌ 不可行，会退化成摘要罗列 |

> ⚠️ **两种模式的产出可信度完全不同**：凭记忆的 6 篇画像**只能用来看"这篇大概在做什么"**；凡是**数据集/指标/得分/算力/模块细节**，都必须走"真读原文"模式（2–3 篇/批）。

**篇数多时按主题分批**，不要按编号顺序硬塞。分批时给每批写明「**这批的重点**」——告诉模型你要用它判断什么，它的回答会更有针对性。

---

## 三、执行纪律（**最重要的一节**）

### 1. 绝不编造数字 ⭐

- **凡无法从论文原文/权威摘要核实的，一律标注 `(未能核实)`。**
- 特别是「**实验得分**」「**超 previous SOTA 多少分**」「**数据集**」「**评估指标**」「**backbone**」「**计算资源**」——**编造一个具体数字比留空危害大得多**。
- 只能拿到摘要时，明确说「**仅能获取摘要，实验细节未能核实**」。
- 找不到某篇时**直接说找不到**，不要用相近论文替代。
- 「未能核实」的**出现次数本身是个质量信号**：数量过少（例如 18 篇里只标 3 处）要警惕——可能是它在编。

### 2. **必须真的去检索并读原文，不许凭记忆** ⭐⭐

**这是本 skill 的第一原则。**

画像里的**数据集、评估指标、backbone、实验得分、超 SOTA 分数、算力、模块细节**——**没有任何一项能靠模型的记忆可靠回答**。实测教训：

- 我最初让网页模型"凭已有知识回答"，结果**同一批 2026 年的论文**，GPT 给出了详尽的数据集/指标/得分，Claude 则标了 **84 处「未能核实」**并明确说「我对这篇论文没有可靠的内容记忆，**不要在申报书里凭我这一节落笔**」。
- 后来派子智能体**真的去打开 arXiv LaTeX 源码**逐字核对，才发现：GPT 的部分细节**无法一手证实**，而真正的一手结论（如 G²LoRA 的调制系数只算当前 iteration 梯度、Co-Teaching 的 LLM 确实每轮微调）**只有读了原文才拿得到**。

**因此，prompt 里必须明确要求**：

> **【执行方式】** 对每一篇，你必须**先检索并定位到该论文的原文**（优先顺序：arXiv abs/HTML/**LaTeX 源码** `arxiv.org/src/<id>` → 出版方页面/ACL Anthology/PMLR/NeurIPS proceedings → 作者主页 PDF → OpenReview），**读取原文后再回答**。
> **不要凭记忆作答，不要用相近论文替代。**
> 引用时给出**读到该内容的 URL**，并尽量附**章节/公式/表号**。

#### 工具循环的防治（不是靠"禁工具"）

**实测**：一次给 6 篇、并要求"逐篇读 PDF"时，Claude 会陷入循环——反复输出「Read 2 pages, searched the web」「Let me read the DRAGON full text…」，**最终产出为零**。

**正确对策是限制与兜底，而不是禁用工具**：

1. **减小批量**：**每批 2–3 篇**（要求读原文时，比"凭记忆"模式的 6 篇要少）。
2. **设工具预算**：写明「**每篇最多使用 N 次检索/读取（建议 6–10 次）；取不到就标注 `未能获取原文` 并跳到下一篇，不要反复重试**」。
3. **要求先给结论再补充**：「**先输出该篇的 14 组答案，再补充引用出处**」——避免它把预算全花在找 PDF 上。
4. **兜底标注**：明确写「若确实取不到原文，写 `未能获取原文` 是**可接受的结果**，比凭记忆编造好得多」。
5. **分批交付**：一次只发一批，收到后再发下一批。

#### 网页端的两个操作坑（发送前检查）

- **功能推荐弹窗挡住输入框** → 发送静默失败（粘贴后 composer 只进 1 个字符）。发送前先检查并关闭弹窗（按钮通常是 "Not now" / "Dismiss"）。
- **额度耗尽时消息会被退回草稿**（停在输入框里没发出去）→ 恢复额度后可直接回车发送，不必重打。
- **校验机制**：发送后**回读 composer 字符数**，与预期长度比对（比值应≈1.0；接近 0 说明没粘进去）。

### 3. 关键论断必须二次核实 ⭐

画像里凡是**你要用来支撑自己论证的关键论断**，必须在画像之外**再单独核一遍**——最好交给**另一个模型或子智能体**，并明确要求**给逐字引用 + 章节定位**。实战教训：

- 缺口论证的两根柱子「**UNIT 是否真的在首个任务后冻结语言侧**」「**DRAGON 的"双向"到什么程度**」，正是这样核出来的：
  - UNIT → 从 arXiv LaTeX 源码拿到 4 处原文（*"only fine-tunes the LLM on the first task"* + *"frozen parameters"*），**论断成立**
  - DRAGON → 确认「**表示层面的双向，不是数据层面的双向**」，子图从不回写
- 更关键的一次：**G²LoRA 的调制系数到底是"当步梯度"还是"跨任务稳定性"**——这个区分直接决定缺口能不能写。读了 §3.3 的公式（$\eta_t=\eta_0\lambda\rho_t$，$\rho_t$ 只由**当前 iteration** 梯度范数算出）才敢下笔。
- 也发现过**需要收窄的地方**：Continual-GraphLLM 的 router **确实用了跨任务历史统计量**（只是 expert 级、非 layer 级）→ 缺口措辞必须写明「**各层**」。

**做法**：画像完成后，单独列一张「**关键论断核实表**」，逐条写明「我的论断 / 核实结果 / 逐字依据 / 依据 URL」。

### 4. 引用陷阱（实测踩到）

| 陷阱 | 实例 |
|---|---|
| **标题讹传** | GaLoRA 流传一份同名硕士报告《…A Lightweight Graph-Aware LLM Framework…》，**正式标题**是《…Parameter-Efficient Graph-Aware LLMs for Node Classification》 |
| **作者名讹误** | Semantic Scholar 把 G²LoRA 作者讹成 "Yu-Han Wang"、"Yi Ding"，**须用出版商/Crossref 形式** |
| **会议名缺卷号** | KDD 2026 会议录分卷，G²LoRA 与 Continual-GraphLLM **都在 V.2**（DOI 前的容器标题带 V.2） |
| **大小写** | GL-Fusion 标题末尾 "model" 是**小写**；Co-teaching 的 t 是**小写** |
| **预印本冒充正式版** | 有的只有 arXiv v1（无 venue），有的被顶会拒过（ICLR 2025/2026 rejected）→ 只能引预印本 |
| **根本没有 arXiv 号** | Continual-GraphLLM **不存在 arXiv 编号**，只有 DOI 与作者主页 PDF → 著录时**不要编一个 arXiv 号** |
| **录用状态是作者自报** | UNIT 的 "Accepted by ACM MM 2026" 只见于 arXiv comment 与模板占位 DOI（`XXXXXXX.XXXXXXX`），ACM DL 打不开、官网无 accepted 列表 → 宜标"作者自报" |

**核准方法（按可靠性排序）**：出版商 Crossref deposit（ACM DL 被 Cloudflare 拦时用这个）→ ACL Anthology / PMLR / NeurIPS proceedings → arXiv API → OpenReview API → DBLP（常被 bot wall 拦，可用 researchr 镜像）。

### 5. 判断"是否已被做过"的三段式

用画像回答「**这件事到底被做到什么程度**」时，按三段拆：

1. **该工作的机制/步骤具体是什么**（不要只看标题和摘要）
2. **它覆盖了我要 claim 的哪一部分**
3. **它明确没做什么**（论文自己承认的局限 + 从其设定可推出的边界）

然后**逐项把已覆盖的从自己的 claim 里删掉**，只留真正剩下的。实战教训：一个"智能体维护知识图谱"的缺口，原本写成"没人做闭环"，画像后发现**四个领域在汇合**（图谱精化/智能体记忆/图级编辑/时序图谱补全），溯源与回滚**已是成熟机制**——必须把 claim 收窄到「**判定对象 + 统一闭环 + 评价口径**」才守得住。

## 四、扩展模式

### 模式 A：单篇精读
用第一至三节。追加要求：「**这篇工作与 XXX（我的方法/我的缺口）的关系是什么？它覆盖了我要 claim 的哪一部分？**」

### 模式 B：批量画像 + 对照表
多篇画像完之后，**再产出一张对照表**：

| 编号 | 任务 | 输入→输出 | 核心机制 | 数据集 | 指标 | backbone | 是否开源 | 算力 | 覆盖我的哪个 claim |
|---|---|---|---|---|---|---|---|---|---|

（这张表最实用——写申报书/相关工作时可**直接引用**。）

### 模式 C：竞品/基线拆解
针对要对比的基线，在第 14 组后追加：
- 它的**超参**是什么？默认设置是多少？
- 复现它**需要什么**（数据、代码、算力、预处理）？
- 它**在什么条件下会失效**？

### 模式 D：科研报告/结题报告精读
14 组问题保留，但把「实验得分/超 SOTA」替换为：
- **报告声称的成果指标**是什么？**有无可核证的数据支撑**？
- **哪些是已完成、哪些是计划**？
- **有无夸大或与事实不符之处**（做事实核查，逐条列出）

## 五、参数化调用模板

```
使用 论文精读 skill，读以下论文并输出 14 组画像：

【论文清单】（编号 + 题目 + 作者 + venue + 年份 + 链接或 DOI）
1. …
2. …

【执行方式】★ 最重要
- 对每一篇，你必须【先检索并定位到论文原文】再回答：
  优先顺序：arXiv abs / HTML / LaTeX 源码(arxiv.org/src/<id>)
           → 出版方页面 / ACL Anthology / PMLR / NeurIPS proceedings
           → 作者主页 PDF → OpenReview
- 【不要凭记忆作答，不要用相近论文替代】
- 引用时给出【读到该内容的 URL】，并尽量附章节 / 公式 / 表号
- 每篇最多使用 <6–10> 次检索或读取；取不到就标注 `未能获取原文` 并跳到下一篇，
  不要反复重试。若确实取不到，写 `未能获取原文` 是可接受的结果，比凭记忆编造好得多。

【分批】每批 2–3 篇；本批重点：<我要用这批判断什么>

【输出纪律】
- 凡无法从原文核实的，标注 (未能核实)，绝不编造数字
  （尤其：数据集 / 评估指标 / backbone / 实验得分 / 超SOTA / 算力）
- 每篇一个小节，按 1-14 编号作答；不要跨篇合并
- 全部答完后加一节「共性观察」(≤200 字)

【额外要求】（可选，但关键论断强烈建议）
- 关键论断核实表：我的论断 / 核实结果 / 【逐字英文引用】 / 依据 URL
- 产出一张对照表（任务/输入输出/机制/数据集/指标/backbone/开源/算力）
```

### 两种模式的选择

| 目的 | 模式 | 批量 |
|---|---|---|
| **快速摸底**："这批论文大概在做什么" | 凭记忆（但仍标注未能核实） | ≤6 篇 |
| **要用它支撑论证 / 写进申报书** | **真读原文** | **2–3 篇** |

> 判断标准很简单：**这个信息如果错了会不会让我在评审面前出错？** 会 → 必须真读原文。
