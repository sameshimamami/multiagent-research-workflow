## 2. 两种执行模式

### 模式 A：dispatch 文件 + 人工桥接（v1，现在就能用，推荐先跑通）

DSH 把生成好的结构化提示词写成 `dispatch/000N-*.md`，由**你**（或你在终端跑的一个脚本）喂给对应智能体：

- 喂给 **Claude Code**（非交互）：
  ```powershell
  # 在项目目录下，读取 dispatch 文件作为提示词
  claude -p (Get-Content -Raw .\research-workflow\dispatch\000N-xxx.md)
  ```
  Claude Code 支持 `-p` / `--print` 非交互输出，`--output-format text|json` 可选。

- 喂给 **hermes**（WSL）：
  ```bash
  wsl -d Ubuntu          # 进入 WSL
  hermes                 # 启动 hermes，粘贴 dispatch 内容执行
  ```
  若 hermes 支持非交互参数，后续可改为 `wsl -d Ubuntu -- bash -lc 'hermes < dispatch.md'`（待实测其 CLI 参数）。

### 模式 B：全自动（v2，目标态）

让 DSH 直接 shell 调用两者。需要**本会话获得更宽沙箱**（`danger-full-access`），
或改用一个不受此沙箱限制的常驻 runner（由你启动 / 计划任务）。
落地时先按 A 跑通全流程，再评估是否升级 B。

## 3. dispatch 文件规范

- 命名：`dispatch/000N-<任务类型>-<简述>.md`（`N` 递增）。
- 内容 = `01-提示词生成规范.md` 的“主模板”产物，含：
  【任务目标】【任务类型】【产出物】【格式规范】【约束】【验收标准】【执行方式】。
- 文件头部加两行元信息：
  ```
  给：hermes / claude
  状态：待执行 / 执行中 / 已完成
  ```
- 执行后，把结果路径回填到文件尾部，或直接告诉 DSH“好了”；DSH 读回验收并更新 `index/`。

---

## 4. 一个任务的完整闭环（示例）

```
1. 你说“记一篇 XX 论文…”
2. DSH 生成提示词 → 写 dispatch/0002-笔记-XX.md（头部标“给 hermes”）
3. 你在终端把该文件内容喂给 hermes
4. hermes 在 Vault 写入笔记；你回一句“好了”
5. DSH 读回笔记验收 → 更新 index/关系索引.md → 回执给你
```
